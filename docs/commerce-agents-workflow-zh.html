02

一次请求的完整旅程

示例请求：“帮我找一个 250 美元以下的双人帐篷”。一个用户 turn 内部可能包含多次模型 round。

1

创建并读取会话

POST /api/session 绑定 user 与随机 session id；聊天时用 X-Session-Id 取回记录。

输出：SessionRecord(messages, state, version)
2

加入用户消息

append_user_turn() 把用户文字，以及聊天外发生的按钮事件，写入 record.messages。

messages 现在以本轮 user message 结尾
3

预取动态上下文

_prefetch() 用 asyncio.gather 并发读取偏好、账户、购物车和一级记忆。

任一读取失败会记录 warning，本轮仍可继续
4

组装 Claude 请求

静态 prompt 与工具列表在初始化时构建；本轮只追加动态 context 和 conversation。

输入：system + tools + messages + tool_choice
5

流式接收模型响应

StreamedRound.relay() 解析文字 delta、工具 JSON 和 UI partial，并不断产出 AgentEvent。

浏览器无需等整轮结束即可显示
6

执行工具

工具参数闭合后，EagerDispatcher 立即启动 Executor；模型可继续生成剩余 block。

工具耗时与模型生成时间重叠
7

工具结果回灌模型

Assistant 的 tool_use 与 User 的 tool_result 一一配对并追加到 messages。

下一 round 能基于业务结果继续决策
8

结束、保存与记忆抽取

无新工具时发出 turn_complete；流结束后保存 session，并后台抽取长期记忆。

持久化 messages + state；异步更新 memory
03

Agent Loop：一个 turn，多个 round

用户只发了一次请求，但 Runtime 可能多次调用 Claude。每次 Claude 调用称为一个 round。

Round input构造请求system、tools、历史消息、tool_choice、thinking
ModelClaude 流式生成text / thinking / tool_use / server tool
Dispatch执行工具Executor → gate → Backend → ToolOutcome
Record追加结果assistant tool_use + user tool_result
Decision继续或结束有工具则下一 round；无工具则完成 turn
↖ 有新的 tool_use：携带更新后的 messages 再次调用 Claude
兜底：达到 max_tool_iterations 后，最后一轮设置 tool_choice = none，强制模型用文字收尾，避免无限工具循环。

05

不要混淆三条数据流

同一次搜索同时产生三种数据，但接收者、生命周期和用途完全不同。

messages

给模型看 · 跨 turn 保存
  • 用户文本
  • assistant 文本与 tool_use
  • user tool_result
  • 下一 round 和下一 turn 重发

AgentEvent

给前端看 · 实时流式
  • text_delta
  • tool_call / tool_result
  • ui / cart_update
  • turn_complete / error

state

给代码 gate 看 · 按 session 保存
  • 本 session 看过的商品
  • provenance 证据
  • 购物车相关状态
  • 不依赖被压缩的 tool result
一句话区分：messages 是模型上下文，AgentEvent 是用户界面协议，state 是服务端业务约束的依据。
06

一个工具调用经过什么

Claude 只产生工具名与参数。真正的副作用必须穿过 Executor 和 Gate 后才能到 Backend。

Claudetool_use
EagerDispatcher并发启动 / 汇合
BaseToolExecutor公共分发与失败梯
Shopping Handler参数与领域逻辑
Gate / Fence来源、上限、安全
Backend真正业务读写
A

ToolOutcome 给两边服务

result_text 变成 tool_result 给模型；events 变成 UI、购物车更新等事件给前端。

B

失败不必终止 turn

非法参数、业务不可用、未知工具通常都转换为错误 ToolOutcome，让模型根据错误修正下一步。

关键安全思想：工具描述是在引导模型；Gate 是代码执行的强制约束。不能因为 prompt 写了“不要乱加购物车”，就省掉 provenance gate。

08

Merchant Agent 不是另一套架构

它复用同一条 Host → Runtime → Executor → Backend 主链，主要替换领域能力和写操作安全策略。

维度Shopping AgentMerchant Agent
服务对象购物顾客商家运营人员
主要读取商品、订单、政策、履约销售、库存、商品、定价、活动
主要写入购物车和用户记忆库存、listing、价格、campaign
核心 Gate商品来源、变体选择、数量上限所有写入先 staged change，再由 Host 审批
共享机制事件流、工具执行框架、skills、fencing、memory、prompt assembly、session

最后压缩成一句话

用户请求先进入 Host；Host 找到会话后调用 Runtime。Runtime 组装上下文并驱动 Claude 的多轮流式循环；Claude 的工具调用交给 Executor，经参数处理、Gate 和 Fence 后访问 Backend。结果一边以 AgentEvent 经 SSE 发给前端，一边作为 tool_result 写回 messages。最终 Host 保存 messages 与 state，并在后台更新长期记忆。
